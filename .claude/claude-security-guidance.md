# Security guidance: metavert-io/hearthloom

Generated by the Security Steward from `security/threat-model.yaml` (model v1, reviewed at ac3b52009a9d). Edit the model, not this file.

A personal second brain: one Rust daemon with an HTTP API, an MCP server for agents, importers for personal data (health, location, messages, email, browsing, photos, contacts, agent sessions) and plugins. The record is among the most sensitive data its owner has.

## What this system protects

- C1 Daemon HTTP API (local)
- C2 MCP server for agents (local)
- C3 The personal record (SQLite) (local)
- C4 Importers and plugins
- C5 Web UI (local)
- C6 API keys (read, ingest, write, grants)
- C7 Releases, updates and the plugin registry (internet)
- C8 CI

## Assumptions

- A1: The daemon listens on the owner's machine or a hosted tenant only, behind the owner's own authentication.

## Keep in mind when changing code

- T-HL-0001 (mitigated, STRIDE:T CWE-1357): A compromised GitHub Action or dependency tampers with what CI builds. Relies on M-HL-0001, M-HL-0002
- T-HL-0002 (mitigated, STRIDE:I CWE-798): A secret is committed to the repository. Relies on M-HL-0003

## Controls that must stay in place

- M-HL-0001: Actions pinned by commit SHA with read-only permissions (`.github/workflows/ci.yml`, `.github/workflows/audit.yml`)
- M-HL-0002: Locked dependencies and a RustSec advisory audit (`Cargo.lock`, `deny.toml`)
- M-HL-0003: Secret scanning in CI (`.github/workflows/secret-scan.yml`)
